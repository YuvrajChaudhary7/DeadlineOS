# Azure Blob Storage design (DP-900)

Store assignment and project workspace binaries in private containers with public access disabled. The API authenticates a user and checks enrollment/deadline or project ownership before writing a random object key; SQL stores only object keys, filenames and timestamps. Keep each submission attempt's file under its own immutable object key so the attempt history remains auditable. Use managed identity, encryption, TLS, size/type allowlists, malware scanning, retention policy and short-lived user-delegation SAS URLs for downloads. Never keep long-lived account keys in source. Local project and submission files use the private Flask instance upload directory. This is a design note; no Azure resources are provisioned.
